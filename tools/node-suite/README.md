# Node.js test-suite harness for pir

This directory runs **Node.js's own test files** against pir's Node surface. It
is a standalone tool, not part of `cargo test`.

The suite is a coverage/gap ledger, not a pass/fail gate: Node's tests encode
the full public API, including features pir deliberately does not implement.
What matters is that every failure has a reproducible classification and a
stable baseline.

- Corpus: nodejs/node `test/parallel` (audited against tag **v24.22.1**)
- Runtime: any `pir.exe` that supports `pir js <file>`
- Reference: a stock Node matching the corpus tag, used only for spot checks

## Layout

```
tools/node-suite/
  runner.py                               # copy corpus, run tests, classify, summarize
  tiers.py                                # rebuild tier A/B/C/D + tier-b-api.txt
  overlay/common-index-process-config.patch  # the only test/common change
  baseline/tier-b-api.txt                 # canonical 438-test public-API subset
  baseline/known-failures.json            # per-test baseline (result + first error)
  README.md
```

Nothing here vendors Node's `test/common`. The corpus is copied at run time and
the patch is applied to the copy. If the copied tree has no `test/package.json`,
the harness adds a `{"type":"commonjs"}` marker in the scratch work root (or copies
an upstream `test/package.json` if present). It lets `test/parallel/*.mjs`
import sibling `test/common` files within pir's entry-package read boundary.
The upstream checkout is not edited.

## Quick start

```sh
# 1. Fetch a corpus once (outside the repo).
git clone --depth 1 --filter=blob:none --sparse --branch v24.22.1 \
  https://github.com/nodejs/node C:/wp/empty/_scratch/node-suite-probe/node
git -C C:/wp/empty/_scratch/node-suite-probe/node sparse-checkout set test

# 2. Prepare a repo-shaped work root and run the 438-test baseline.
python tools/node-suite/runner.py \
  --pir   target/debug/pir.exe \
  --pir-root C:/wp/empty/_pir_node_wt \
  --corpus C:/wp/empty/_scratch/node-suite-probe/node \
  --work   C:/wp/empty/_scratch/ns-agent/work-root \
  --out    C:/wp/empty/_scratch/ns-agent/runs/current \
  --list   tools/node-suite/baseline/tier-b-api.txt \
  --timeout 8 --jobs 5

# 3. Run every test starting with one of several prefixes.
python tools/node-suite/runner.py ... --prefix test-fs- --prefix test-zlib-

# 4. Refresh the baseline after an intentional change.
python tools/node-suite/runner.py ... --write-baseline tools/node-suite/baseline/known-failures.json
```

`--work` may be reused with `--skip-copy`; otherwise `test/{common,fixtures,
parallel}` is copied on every run and the patch is re-applied. `--work`
defaults to `<out>/work`.

Outputs in `--out`:

| File | Contents |
|---|---|
| `results.jsonl` | one record per test: result, exit code, duration, module, first error |
| `logs/<test>.log` | combined stdout/stderr |
| `summary.json` | binary sha256/mtime, shim mode and source fingerprints, suite tag/commit, counts, shares, per-module table, duration percentiles, env |
| `known-failures.json` | baseline-shaped snapshot of the same run |
| `testtmp/<id>/` | per-test `NODE_TEST_DIR` (fresh `.tmp.<id>` under it) |

## Tiers

`tiers.py` rebuilds the manifests from a corpus checkout:

```sh
python tools/node-suite/tiers.py \
  --corpus C:/wp/empty/_scratch/node-suite-probe/node \
  --out    /tmp/pir-tiers \
  --check  tools/node-suite/baseline/tier-b-api.txt
```

First-match partition of `test/parallel/*.js`:

| Tier | Definition |
|---|---|
| **A** | Does not require `../common`; runs against stock `pir js` with no shim (5 files; 3 pass). |
| **B** | Needs only the vendored `common` shim. Runnable, not necessarily passing. Current partition: 2,603 files. |
| **C** | Needs a missing feature: `node:test`, `worker_threads`, `child_process`/`process.execPath`, or a CLI flag. Current partition: 1,076 files. |
| **D** | Out of scope: internal modules/`--expose-internals`, inspector, `test-v8-*`, addon/napi/wasi/sea. Current partition: 499 files. |

The audit in `docs/node-test-suite-audit.md` quotes *category sums* (a file can
match several blockers), so its 5 / 2,640 / 1,027 / 511 table is not a disjoint
partition. `tiers.py` reports a disjoint partition; the deltas are overlap.

`baseline/tier-b-api.txt` is the stricter **438-test public-API subset**: the 11
families below, no internal/worker/child/net/cluster/dgram/http/tls/inspector/
addon use, no `// Flags:` other than `--no-warnings`. It is regenerated by
`tiers.py` and checked byte-for-byte; one file (`test-buffer-includes.js`) is a
documented manual drop from the original curation.

```
fs stream zlib buffer path util events assert querystring url string-decoder
```

Regenerating the list is deterministic. Do not hand-edit it; change the rules in
`tiers.py` and re-run `--check`.

## Environment model

Each test runs in its own `pir js` process. This is mandatory: `common.mustCall`
accounts for calls in an `exit` handler, so sharing a process turns missing
calls into false PASSes.

Per test:

| Variable | Value | Why |
|---|---|---|
| `PIR_EXT_BYTECODE` | `0` by default | exercise the shims from source, not AOT blobs |
| `PIR_EXT_SHIM_SRC` | `1` by default | live override for virtual-module shims from `crates/pir-core/src/extensions/api/js/*.txt` |
| `PIR_AGENT_DIR` | `<agent-root>/agent-<run>-<id>` | fresh per-test agent state |
| `NODE_TEST_KNOWN_GLOBALS` | `0` | pir leaks host globals; see deviations |
| `TEST_SERIAL_ID`, `TEST_THREAD_ID` | unique per test | unique `tmpdir` name |
| `NODE_TEST_DIR` | `<out>/testtmp/<id>` per test | fresh tmpdir per test |
| `NODE_COMMON_PORT` | `12346 + slot` | avoid port collisions |
| `TEST_PARALLEL` | unset | `common.PORT` throws when it is set |

`--env KEY=VALUE` overrides any of these. In particular, force the embedded
shims with:

```sh
--env PIR_EXT_SHIM_SRC=0 --env PIR_EXT_BYTECODE=1
```

With source lookup enabled (the default), pass `--pir-root` pointing to the
checkout recorded when that `pir` binary was built. The runner cannot infer
that root from the executable path; the flag identifies the tree to hash, not
an override for pir's lookup. It hashes the whole shim tree, but pir consults
the live files only for virtual modules; the prelude and the assembled global
boot bundles always use their embedded sources. A missing or unreadable
initial tree is an error.
`harness.env` records the effective switch values and `harness.shim_mode` their
configured lookup order. With both switches enabled, bytecode takes precedence
where available, but a fallback can still read from the live checkout. With
both disabled, pir uses embedded source, not bytecode. No source hash is
recorded when source lookup is disabled.

### Agent-dir sandbox rule (important)

pir confines filesystem writes to **`parent(PIR_AGENT_DIR)`**. If the agent dir
is nested (e.g. `<root>/agents/slot-0`), then `<root>/work` and `<root>/runs`
are outside the writable root and every `tmpdir.refresh()` fails with `EACCES`.
The runner therefore creates agent dirs as direct children of a common root
(`os.path.commonpath([work, out])`, or `--agent-root`). If you build your own
invocation, keep `PIR_AGENT_DIR` one level below the directory that contains
the work root.

### Classification

`TIMEOUT` takes precedence over all output. A nonzero exit or a numbered TAP
`not ok` point without `# SKIP` or `# TODO` is a failure, even if other tests
skipped. Failure diagnostics distinguish `UNSUPPORTED` (`ERR_NOT_SUPPORTED`
or the legacy unsupported messages), `ASSERT` (`AssertionError` or
`ERR_ASSERTION`), and `ERROR` (everything else).

With exit 0 and no TAP failure, `SKIP` requires a `1..0 # Skipped` plan or TAP
skip points, with no non-skipped test points. A successful `describe`/suite
wrapper does not count as a test. A mix of skipped and successful or TODO
points is `PASS`, as is an ordinary successful non-TAP run. Run-specific paths
and long numbers in error hints are normalized for baseline comparison.

The standalone verdict and provenance tests need only Python's standard
library: `python -I tests/test_node_suite_runner.py` from the pir checkout.

## Known deviations

1. **Suite version vs runtime version.** Corpus is v24.22.1; this binary
   reports `v24.19.0`. Version-gated tests may legitimately differ.
2. **`NODE_TEST_KNOWN_GLOBALS=0`.** pir leaks host/`__pir*` globals. With the
   check enabled, `common`'s exit handler throws before `mustCall` accounting
   and missing calls become false PASSes. Disabling it is required for honest
   exit codes; the leak itself is a runtime defect.
3. **No CLI flags.** `pir js` does not parse Node flags. The 438 baseline is
   deliberately flag-free (`--no-warnings` is the only tolerated flag). Tests
   with other flags belong to Tier C and are not run.
4. **`process.execPath` is not node-compatible.** 475 parallel tests re-spawn
   themselves; those hang or fail. `process.execPath` points at `pir.exe`,
   where `<exe> file.js` starts the agent, not `pir js file.js`.
5. **Repo-shaped work root.** The runner lays out `<work>/test/{parallel,
   common,fixtures}` and runs from `<work>`, matching Node's repo layout. This
   makes `../../test/common/...` and literal `test/fixtures` paths resolve.
6. **Windows symlink privilege.** Symlink/chown tests fail with `EPERM` when
   Developer Mode is off. Node's `common.canCreateSymLink` is supposed to skip
   these; under pir it does not.
7. **Sparse Intl, not versions.** The current stub publishes
   `node/v8/uv/zlib/brotli/ares/modules/napi/openssl/sqlite/unicode/icu`, so
   `common.hasCrypto` is true. `hasIntl` is still false because there is no ICU
   locale data, so Intl tests skip truthfully. A run pinned to an older binary
   (before the version table was populated) still reports missing crypto.
8. **Timeouts.** 8 s versus Node's 120 s. The whole process tree is killed with
   `taskkill /F /T` on Windows. Timeouts are real hangs, not slow successes.
9. **Source-shim mode is a live checkout.** `PIR_EXT_SHIM_SRC=1` reads
   `crates/pir-core/src/extensions/api/js/*.txt` from the checkout recorded at compile time.
   If another process edits a shim during a run, results are not a single
   snapshot. `summary.json` records the explicit checkout root, a tree hash
   before/after, and `stable: false` if the samples differ or the final tree
   cannot be read. Disable source lookup (`PIR_EXT_SHIM_SRC=0`) for a run pinned
   to the binary, or wait for the tree to settle.
10. **No Node reference run by default.** Failures are attributed against the
    corpus semantics; validate a sample with the matching `node.exe` when in
    doubt. The old 58-test sample was 58/58 on Node v24.22.1.

## Refreshing the corpus

The corpus is not committed (51 MB of fixtures, 24 MB of tests). To move to a
new Node tag:

```sh
git -C <corpus> fetch --depth 1 origin tag v24.XX.Y
git -C <corpus> checkout v24.XX.Y
git -C <corpus> sparse-checkout set test
python tools/node-suite/tiers.py --corpus <corpus> --out /tmp/pir-tiers
# review /tmp/pir-tiers/tier-*.txt, then update baseline/tier-b-api.txt
python tools/node-suite/runner.py ...   # refresh known-failures.json
```

The harness records the corpus tag/commit, so old and new runs are
distinguishable. Keep runs outside the repo (`target/` is also acceptable but
not committed); the repository only carries the manifests and baseline.

## Comparing runs

`known-failures.json` maps every test to `{result, exit_code, duration_ms,
module, first_error, skip_reason}` plus the binary and suite metadata. Compare
two files on `result` and `first_error`; ignore `duration_ms` and paths (they
are already normalized to `<out>`/`<testtmp>` for the latter). A regression is a
test whose result got worse *outside* the baseline; the baseline itself records
the known failures, so the job can fail only on new ones.
